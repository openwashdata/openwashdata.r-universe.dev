# openwashdata.r-universe.dev

The package registry for <https://openwashdata.r-universe.dev>.

`packages.json` lists the repositories r-universe builds. Install any of
them with:

```r
install.packages("washmalawi", repos = "https://openwashdata.r-universe.dev")
```

or, from the index package:

```r
owdata::owd_install("washmalawi")
```

## What is listed

Every published openwashdata data package, plus the two tools `washr`
and `owdata`. A data package counts as published when its
`CITATION.cff` carries a Zenodo DOI.

The two tools are listed for different reasons. `owdata` is not on CRAN
and has no other distribution channel, and `owdata::owd_install()`
points at this repository, so it has to be here. `washr` is on CRAN and
installable from there whatever this file says; it is listed so the
universe also carries a development build, installable with plain
`install.packages()` without a toolchain.

Both names are hard-coded by the generator and a unit test asserts their
presence, because this file is the whole universe once it exists: a
custom registry takes precedence over the auto-generated one that
r-universe builds by scanning CRAN for GitHub links, and the build
system switches over as soon as it appears. An entry dropped from here
disappears from the universe with no error anywhere.

## How it is updated

`packages.json` is generated by the weekly harvest in
[openwashdata/owdata](https://github.com/openwashdata/owdata) as
`data-raw/packages.json`. The harvest report says when the generated file
differs from the copy committed here, and the maintainer copies it over
by hand. Packages are published a few times a year, so this is minutes
per year.

There is no sync workflow and no organisation token, by design. See
`dev/decisions-2026-09.md` in the owdata repository, section 4.

## Editing by hand

Do not. Change the harvest or the exclusion list in owdata instead, so
the generated file and this copy cannot drift apart.
